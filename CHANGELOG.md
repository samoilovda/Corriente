## [0.3.0] — versionCode 3

### Аудит 2026-09-23 (`docs/AUDIT_2026-09-23.md`, задачи A0.1–A3.15)

Один коммит на задачу, сообщение начинается с ID. Схема БД **v6 → v7** (`MIGRATION_6_7`: индекс поиска `txn_fts`).

**P0 — падения и неверные данные**
- **A0.1** Правка повторяющегося правила больше не создаёт лишнюю операцию: `nextRunOn` не трогается, если правило
  не изменилось, а при изменении считается строго после последней созданной операции.
- **A0.2** Калькулятор суммы не падает при переполнении (`× ÷ +`): сообщение «Слишком большое число», «Сохранить»
  недоступна; `×` не переполняется на промежуточном произведении.

**P1 — инварианты, бэкап/импорт, откат**
- **A1.1** «Показать ещё» в списке операций появляется, когда за окном есть операции (запрос к БД).
- **A1.2** Снимок виджета пересчитывается по актуальной дате при живом процессе (смена суток/месяца).
- **A1.3** Экран «Автобэкап» не падает при потере доступа к папке; удалённый файл — `Failed`, не краш.
- **A1.4** «Настройки», «Блокировка», «Динамика по счёту» прокручиваются.
- **A1.5** Повторяющиеся: изоляция ошибок правил, атомарная материализация (правило + `recordRun` в одной транзакции).
- **A1.6** Валюту счёта нельзя сменить, если на него ссылается правило.
- **A1.7** Бюджеты и правила не ломают удаление, слияние (при конфликте бюджетов остаётся бюджет целевой категории)
  и откат импорта; `deleteIfUnused` возвращает причину отказа.
- **A1.8** Импорт: конфликт валют счёта разрешается «разделением по валютам»; без решения импорт заблокирован.
- **A1.9** Откат импорта удаляет созданные им счета (без операций) и сообщает, что оставлено.
- **A1.10** Поиск по заметке нечувствителен к регистру кириллицы и префиксный (`unicode61`, схема v7); «ё» и «е»
  различаются (зафиксировано тестом).
- **A1.11** Настоящий экспорт `6.json`; тест полной цепочки миграций через `Room.databaseBuilder`.
- **A1.12** `BackupRepository.validate` возвращает структурированные `BackupProblem` и ловит всё, что ломает
  восстановление (формат валют, enum'ы, дубли, I-15, вложенность категорий).
- **A1.13** Автобэкап пишет через `.part` + переименование; битые файлы не занимают слот ротации.
- **A1.14** Экспорт бэкапа читает таблицы одним снимком (транзакция).

**P2 — производительность, UX, редкие краши**
- **A2.1** SAF-операции экспорта/импорта — на IO, в `try`, с сообщением «Сохранено»/«Не удалось сохранить».
- **A2.2** Удаление счёта/категории: кнопка только для неиспользуемых, подтверждение, причина отказа.
- **A2.3** Бюджет/правило с некорректным вводом не закрывают форму молча.
- **A2.4** Полосы бюджета — только в режиме «Месяц» и по действующим бюджетам; имена архивных категорий; запрет

- **A2.5** Вид категории обязан совпадать с видом операции (быстрый ввод из виджета, репозиторий, импорт). Восстановление

### После R6 — исправления по обратной связи

- **Навигация**: кнопка «Создать счёт» на экране ввода операции больше не ломает нижнюю
  навигацию. Раньше экран ввода оставался в стеке под «Счетами», и `saveState`/`restoreState`
  при следующем тапе по «Операциям» восстанавливали именно его (под-экран без нижней панели) —
  до вкладки «Операции» было не добраться без перезапуска приложения. Теперь экран ввода
  убирается из стека, а переход выполняется тем же манёвром, что и сама нижняя навигация
  (`CorrienteNavHost`, тест `CreateAccountFromEntryInstrumentedTest`).
- **Калькулятор суммы**: добавлены умножение и деление (`× ÷`). Второй операнд трактуется как
  множитель, а не сумма (`10 ₽ × 3 = 30 ₽`, `100 ₽ ÷ 4 = 25 ₽`); результат округляется до
  минорной единицы валюты. Деление на ноль оставляет накопитель без изменений
  (`core/money/Calculator.kt`, `CalcOp.TIMES`/`CalcOp.DIVIDE`).
- **Типовые категории «из коробки»**: пустой список категорий наполняется базовым набором —
  20 категорий расходов и 9 доходов с иконками-эмодзи (`core/data/seed/DefaultCategories.kt`).
  Кладётся при первом создании БД и миграцией схемы **v5 → v6** для уже установленных копий —
  в обоих случаях только если категорий ещё нет, чтобы не спорить с заведёнными вручную.

### Найдено ревью-проходом по коду — исправлено

- **Восстановление бэкапа с импортированными операциями падало.** `BackupRepository.restorePayload`
  вставляло `txn` до `import_batch`, а `txn.import_batch_id` — настоящий Room `@ForeignKey` на
  `import_batch(id)`; SQLite проверяет внешние ключи сразу при `INSERT`. Любой бэкап с хотя бы
  одной операцией, попавшей в БД через импорт из Monefy, ронял восстановление
  `SQLITE_CONSTRAINT_FOREIGNKEY` и откатывал всю транзакцию. Порядок вставки поправлен
  (`import_batch` — перед `txn`), добавлен регрессионный тест
  `restoreRoundTripsATransactionLinkedToAnImportBatch`.
- **Замок приложения переспрашивал биометрию/PIN при повороте экрана.** `AppLockCoordinator`
  считал число запущенных Activity процесса и заново запрашивал разблокировку, когда оно падало
  до нуля — но ни одна из запертых Activity не объявляет `android:configChanges`, и поворот
  экрана (или смена темы/локали) полностью пересоздаёт Activity (`onStop`→`onDestroy`→`onCreate`→
  `onStart`), на мгновение обнуляя счётчик. В режиме «при каждом открытии» это означало: разблокировал
  приложение, повернул телефон — снова экран замка. Теперь `Activity.isChangingConfigurations`
  гасит ровно один повторный запрос на пересоздание, вызванное поворотом.
- **Двойной тап «Сохранить» создавал операцию/перевод/бюджет/повторяющееся правило дважды.**
  `TxnEntryViewModel`, `TransferEntryViewModel`, `BudgetsViewModel` и `RecurringViewModel`
  проверяли только валидность формы — без флага «запись уже в полёте», как уже было сделано в
  `QuickEntryViewModel` (быстрый ввод из виджета). Кнопка/пункт «Сохранить» оставались нажимаемыми,
  пока корутина записи не долетит до БД и экран не начнёт закрываться, — второй тап успевал
  создать дубликат. Все четыре ViewModel получили тот же флаг `saving`, что и виджет; регрессионный
  тест `a second save call while the first is settling is a no-op`.
