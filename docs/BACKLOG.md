# Бэклог

Замеченное за пределами текущей задачи (BUILD_PLAN.md §0, правило 8). Не трогать в рамках
чужой задачи — разбирать отдельно.

- **Копии БД «до миграции/восстановления» не восстановить из приложения** (A2.15, `[решение]`).
  Копии лежат в `databases/pre-migration/` (последние 3), UI для них нет — вернуться к ним можно только через
  adb/root. Развилка для пользователя: кнопка «Восстановить копию, сделанную перед обновлением/восстановлением»
  на экране «Автобэкап» через тот же путь `restore` с проверкой, либо экспорт копии в SAF. Не реализовано:
  решение не принято.
- **`import_alias`: таблица и DAO есть, UI создания алиасов нет** (A3.3, `[решение]`). Пишется только восстановлением
  бэкапа и читается импортом. Развилка для пользователя: либо сделать экран алиасов категорий/счетов при импорте
  Monefy, либо убрать таблицу из плана (тогда миграция схемы). Пока оставлено как есть.
- **Тестовые данные в `testdata/monefy_sample.expected.md` упоминают `[перевод без пары]`** — теперь имя категории
  зависит от локали (A2.13); файл описывает русскую локаль, менять не нужно, но при появлении английского
  эталона добавить рядом `[unpaired transfer]`.

  + задача `verifyInvariantGuards` как замена Detekt; логика покрыта `InvariantGuardsTest`,
  формулировки в BUILD_PLAN.md §0/§1.5/T0.5 обновлены.
- **Нижняя навигация видна на под-экранах.** → `CorrienteDestination.isTopLevelRoute`;
  `bottomBar` в `CorrienteNavHost` рисуется только на четырёх корневых маршрутах.
- **Импорт Monefy: NEEDS_REVIEW разбирается только «как есть».** → `applyReviewDecisions`
  (`:core:data`) + карточки на экране dry-run: принять / не склеивать / считать одной
  валютой / ввести точные суммы / выбрать валюту счёта. Решение применяется к плану до
  записи. Остаётся узкое место: при неоднозначной склейке нельзя выбрать конкретную пару
  из нескольких, только принять порядок строк или расклеить всю группу — для реального
  файла (2 одинаковых перевода в день) этого достаточно.
