## Разобрано

- **Копии БД «до миграции/восстановления» не восстановить из приложения** (A2.15). → Экран «Автобэкап»: раздел
  «Копии перед обновлением и восстановлением», кнопка «Восстановить» (метка `restore-pending` + подмена файла при
  старте до открытия БД, `PreMigrationBackup.applyPendingRestore`; текущая БД сохраняется как `pre-restore-copy`).
  Проверено на эмуляторе.
- **`import_alias`: UI создания алиасов нет** (A3.3). → Таблица оставлена (формат бэкапа и схема не меняются);
  на экране dry-run импорта Monefy появился блок «Сопоставление категорий»: категорию из файла можно слить в
  существующую, выбор запоминается в `import_alias` и применяется при следующих импортах. Алиасы счетов/валют
  по-прежнему не используются.

- **Detekt не подключён.** → Осознанно зафиксирован файловый скан `InvariantGuards` (buildSrc)
  + задача `verifyInvariantGuards` как замена Detekt; логика покрыта `InvariantGuardsTest`,
  формулировки в BUILD_PLAN.md §0/§1.5/T0.5 обновлены.
- **Нижняя навигация видна на под-экранах.** → `CorrienteDestination.isTopLevelRoute`;
  `bottomBar` в `CorrienteNavHost` рисуется только на четырёх корневых маршрутах.
- **Импорт Monefy: NEEDS_REVIEW разбирается только «как есть».** → `applyReviewDecisions`
  (`:core:data`) + карточки на экране dry-run: принять / не склеивать / считать одной
  валютой / ввести точные суммы / выбрать валюту счёта. Решение применяется к плану до
  записи. Остаётся узкое место: при неоднозначной склейке нельзя выбрать конкретную пару
  из нескольких, только принять порядок строк или расклеить всю группу — для реального
  файла (2 одинаковых перевода в день) этого достаточно.
