# План доработки интерфейса Corriente — к исполнению

Рабочее задание для агента-исполнителя: довести UI Android-приложения (`:app`) до современного
уровня Material 3 (2025–2026). Источник — обзор экранов на эмуляторе (API 36, светлая тема,
режим для левшей) и кода `app/src/main/kotlin/com/corriente/app/ui` от 2026-10-17, коммит `6c99db9`.

Правила исполнителя — [`BUILD_PLAN.md`](BUILD_PLAN.md) §0, инварианты —
[`INVARIANTS.md`](INVARIANTS.md). Ниже — только то, что специфично для этого плана.

---

## 0. Правила работы (дополнение к BUILD_PLAN §0)

1. **Один коммит на задачу**, сообщение начинается с ID: `UI-1.2: даты по-человечески`.
2. **Перед коммитом** — `./gradlew check`; для задач, задевающих экраны с инструментальными
   тестами (`txnentry`, `settings`, `autobackup`), ещё `./gradlew connectedCheck` на эмуляторе
   `corriente`. Плюс ручной смоук: скриншот изменённого экрана в светлой **и тёмной** теме
   (`adb shell cmd uimode night yes|no`), с крупным шрифтом (`settings put system font_scale 1.3`)
   и в режиме для левшей.
3. **Логика — в чистые функции с тестами.** Форматирование дат, выбор цвета суммы, группировка —
   всё, что не сам Composable, выносится и тестируется (BUILD_PLAN §0 п.2).
4. **I-8 не нарушать ни ради красоты:** ни одна «итоговая плашка» не суммирует разные валюты.
5. **Десктоп (`:desktop`) не трогаем**, кроме общих файлов, которые он уже переиспользует
   (`CategoryIconVectors.kt`). Перенос визуальных решений на десктоп — отдельной задачей в BACKLOG.
6. **Новые зависимости** (BUILD_PLAN §1.3) — только перечисленные в §1 ниже и только после
   согласования с пользователем. Без согласования задача, которой она нужна, пропускается.
7. Строки — только через ресурсы, в EN и RU одновременно (не повторять незакрытый R6.3).

## 2. Этап UI-1 — основа визуального языка (6–10 ч)

После этого этапа приложение выглядит цельно: свои цвета, единые даты, читаемые суммы.

**UI-1.1 Тема: своя палитра, типографика, формы.** В `CorrienteTheme` — собственные
`lightColorScheme`/`darkColorScheme`, построенные от одного seed-цвета (бирюзово-синий, «течение»;
сгенерировать M3-тона, зашить константами в `theme/Color.kt`). Material You остаётся по умолчанию
на Android 12+, своя палитра — фолбэк и вариант при выключенном переключателе (UI-1.5).
`theme/Type.kt`: `Typography` на системном шрифте, но со стилем для денег —
`MoneyTextStyle` = `fontFeatureSettings = "tnum"` (табличные цифры), `FontWeight.Medium`.
`theme/Shape.kt`: `Shapes` с `medium = 16.dp`, `large = 24.dp` (карточки и листы).
Семантические цвета денег — `CorrienteColors.income/expense` через `CompositionLocal`, с парами
для тёмной темы (без хардкода `Color.Green/Red` по экранам).
*Готово:* тест на контраст `income`/`expense` к `surface` ≥ 4.5:1 в обеих темах (чистая функция
относительной яркости по WCAG); скриншоты 2 тем × Android 12+/«без динамических цветов».

**UI-1.2 Даты по-человечески.** Чистая функция `formatDayHeader(date, today, locale)`:
«Сегодня», «Вчера», «пт, 17 октября», для другого года — «17 октября 2025». `formatMonth(yearMonth,
locale)` — «Октябрь 2026» (именительный падеж через `TextStyle.FULL_STANDALONE`). Применить в
`DayHeader`, на вводе операции/перевода (поле даты → `AssistChip` с иконкой календаря и текстом
«Сегодня»), в периоде отчёта (вместо `10.2026`), в истории импорта и автобэкапе.
*Готово:* тесты форматтеров на EN/RU, смену года, «вчера» через границу месяца; поиск по
`ui/` — ни одного `date.toString()` в отображении.

**UI-1.3 Суммы: цвет, вес, выравнивание.** Composable `MoneyText(text, kind)` в `ui/common`:
`MoneyTextStyle`, доход — `income`, расход — `onSurface` (не красный: расход — норма), перевод —
`onSurfaceVariant`. Использовать в строке операции, заголовке дня, счетах, отчёте, бюджетах.
Выбор цвета — чистая функция `moneyTone(kind, isNegativeBalance)`, тест.
*Готово:* тест `moneyTone`; на скриншоте списка суммы выровнены по правому краю ровным столбцом.

**UI-1.4 Иконки: один стиль.** Правило: в нижней навигации невыбранный пункт — `Outlined`,
выбранный — `Filled` (поле `selectedIcon` в `CorrienteDestination`); в остальном UI — `Outlined`
(`Rounded`, если решим так в UI-1.1 — одно семейство на всё). Заменить устаревшие
`Icons.Filled.List` и др. на `Icons.AutoMirrored.*`.
*Готово:* сборка без deprecation-предупреждений про иконки; guard в `InvariantGuards`, запрещающий
`Icons.Filled.` вне `navigation/` (если вписывается в существующий механизм без усложнения).

**UI-1.5 Переключатель «Цвета обоев».** В «Настройках» → «Оформление»: тема (системная/светлая/
тёмная) и «Цвета из обоев» (только Android 12+). Хранение — `UiPrefs` (как режим для левшей).
*Готово:* тест чтения/записи настроек; смена применяется без перезапуска.

**Приёмка этапа UI-1:** скриншоты всех четырёх корневых экранов в двух темах — ни одной ISO-даты,
суммы столбцом, нет фиолетового «дефолта» при выключенных цветах обоев.

## 3. Этап UI-2 — экраны (10–16 ч)

**UI-2.1 Операции: верхняя панель и липкие заголовки.** `TopAppBar` с
`enterAlwaysScrollBehavior` (панель уезжает при прокрутке вниз). Действия: поиск остаётся иконкой,
фильтр — иконка с `BadgedBox` (точка, если фильтр активен), экспорт и «перевод» — в меню «⋮»
(перевод и так доступен с FAB, см. UI-2.2). Заголовки дней — `stickyHeader` в `LazyColumn`,
на фоне `surfaceContainer`. Плашку «Balance» — из красного-на-сиреневом в
`surfaceContainerHigh` с `MoneyText` (красный — только если баланс < 0, и только у суммы).
*Готово:* `connectedCheck` зелёный; вручную на 7 000 строках заголовок дня прилипает, прокрутка
плавная (как в T1.6).

**UI-2.2 Операции: FAB.** Сохранить сплит «−»/«+» (T1.5a, режим для левшей), но привести к M3:
основная «−» — `FloatingActionButton` стандартного размера с `primaryContainer`, «+» —
`SmallFloatingActionButton` с `secondaryContainer`; при прокрутке вниз обе прячутся
(`AnimatedVisibility` + `slideInVertically`), при прокрутке вверх — возвращаются.
Долгий тап по «+» — меню «Доход / Перевод».
*Готово:* тест логики видимости по направлению прокрутки (чистая функция от дельты);
инструментальный тест сплит-FAB не ломается.

**UI-2.3 Пустые состояния.** Общий Composable `EmptyState(icon, title, body, action?)` в
`ui/common`: крупная иконка в тональном круге, заголовок, пояснение, кнопка. Различать
«в этом месяце пока нет операций» (кнопка «Добавить расход») и «по фильтру ничего не найдено»
(кнопка «Сбросить фильтр»). То же для «Отчёта», «Бюджетов», «Регулярных», «Истории импорта».
*Готово:* тест выбора варианта пустого состояния (`filterActive`, `hasEarlier`) в ViewModel.

**UI-2.4 Настройки: группы и иконки.** Секции с заголовками: «Данные» (валюты, категории, бюджеты,
регулярные), «Импорт и бэкап» (Monefy, история, автобэкап, синхронизация), «Оформление» (язык,
тема, цвета, режим для левшей), «Безопасность» (блокировка), «Виджет», «О приложении». Каждый
пункт — `ListItem` с ведущей иконкой; секции — скруглённые группы (`Surface` `shape = large`,
`surfaceContainerLow`) без линий-разделителей внутри.
*Готово:* `SettingsScrollInstrumentedTest` и `BackupRestoreConfirmationInstrumentedTest` зелёные
(обновить селекторы, если нужно); все пункты доступны с `font_scale 1.3`.

**UI-2.5 Счета: карточки.** Сверху — по одной карточке на валюту с итогом (I-8: одна валюта —
одна карточка, горизонтальный `LazyRow`, если валют > 1). Ниже — счета группами по валюте в
скруглённых контейнерах; слева у счёта — цветной круг с иконкой типа (наличные/карта/накопления)
вместо серого пустого кружка; спарклайн — как сейчас, справа. Архивные — свёрнутой группой внизу.
*Готово:* тест ViewModel: итоги карточек равны текущим итогам групп (регресс I-8).

**UI-2.6 Отчёт: переключатели.** «Расход/Доход» — `SingleChoiceSegmentedButtonRow` на всю ширину;
период «Месяц/Квартал/Год/Свой» — второй `SegmentedButtonRow` или `FilterChip`-ряд, визуально
отличный от первого; навигация по периоду — заголовок «Октябрь 2026» (UI-1.2) со стрелками.
«CSV» и «Курсы обмена» — в меню «⋮» верхней панели (курсы можно оставить иконкой).
*Готово:* тест ViewModel не меняется по логике; скриншот — два ряда переключателей различимы.

**UI-2.7 Ввод операции: клавиатура и категория.** Клавиши — тональные скруглённые кнопки
(`FilledTonalButton`, `shape = large`), операторы — `secondaryContainer`, «=» скрыта, пока нечего
вычислять (на её месте — «00» или пусто, решить по месту). Тактильный отклик на нажатие
(`LocalHapticFeedback`, `HapticFeedbackType.TextHandleMove`/`KeyboardTap`). Кнопка
«CHOOSE CATEGORY» → `Button` с обычным регистром «Выбрать категорию»; если в форме уже задана
категория — показывать её чип с иконкой и цветом. Счёт — чип рядом с датой.
*Готово:* `TxnEntryFlowInstrumentedTest` и `ArchivedAccountEditInstrumentedTest` зелёные; вручную —
ввод с калькулятором (×, ÷) не сломан, в режиме для левшей раскладка зеркальна как прежде.

**Приёмка этапа UI-2:** пользователь проходит основной сценарий (открыть → добавить расход →
посмотреть отчёт → проверить баланс) без единого капс-лока, ISO-даты и «пустого» экрана без подсказки.

## 4. Этап UI-3 — движение и жесты (8–12 ч)

**UI-3.1 Анимации.** Минимальный набор, без самоцели: `Modifier.animateItem()` у строк списка
операций, счетов, категорий; `AnimatedContent` для смены месяца над кольцом (сдвиг влево/вправо по
направлению); `animateFloatAsState` для дуг кольца и полос бюджетов; `AnimatedContent` для цифр
суммы на вводе. Уважать «Убрать анимацию» системы (`Settings.Global.ANIMATOR_DURATION_SCALE == 0`
— Compose учитывает сам, проверить).
*Готово:* вручную с включёнными и выключенными системными анимациями; 7 000 строк — без
просадки кадров (Profile GPU rendering / `adb shell dumpsys gfxinfo`).

**UI-3.2 Свайпы по операции.** `SwipeToDismissBox`: свайп влево — удалить (без диалога, со
снекбаром «Удалено · Отменить» на 5 с; отмена восстанавливает ту же строку с тем же UUID),
свайп вправо — «Повторить» (открыть ввод с той же категорией/счётом/суммой и сегодняшней датой).
В режиме для левшей направления не зеркалить (свайп — не кнопки).
Удаление переводов и операций из импорта — по текущим правилам (диалог, если они есть).
*Готово:* тест ViewModel «удалить → отменить → строка идентична» (UUID, `created_at`, синк-поля);
`connectedCheck`.

**UI-3.3 Адаптивная раскладка.** При ширине ≥ 600dp — `NavigationRail` слева вместо нижней панели;
≥ 840dp — список операций + детали/ввод в две панели (list-detail вручную, без новой зависимости,
см. §1). Решение о раскладке — чистая функция `navLayoutFor(widthDp)`.
*Готово:* тест `navLayoutFor`; скриншоты на эмуляторе в ландшафте и на AVD-планшете
(`Pixel Tablet`).

**UI-3.4 Предиктивный «назад».** `android:enableOnBackInvokedCallback="true"` в манифесте,
проверить, что `navigation-compose` 2.9 даёт системную анимацию на под-экранах, а
`BackHandler`'ы в листах/диалогах не ломают её. Если для этого нужен апгрейд
`navigation-compose` — отдельным коммитом с согласованием.
*Готово:* вручную жест «назад» на API 36 показывает превью предыдущего экрана; несохранённая
форма ввода по-прежнему спрашивает подтверждение.

**Приёмка этапа UI-3:** приложение откликается на действия движением и вибрацией, удаление
операции отменяемо, на планшете/в ландшафте нет растянутой телефонной вёрстки.

## 5. Вне плана (в BACKLOG при необходимости)

- Перенос визуального языка UI-1 на десктоп (`:desktop`) и виджет (`:widget`, Glance).
- Material 3 Expressive (`ButtonGroup`, `FloatingActionButtonMenu`, morphing-формы) — пока API
  экспериментальные; вернуться, когда станут stable в `compose-bom`.
- Иллюстрации для пустых состояний (сейчас — иконки; картинки требуют дизайнера).
- Темы-акценты на выбор пользователя (несколько seed-цветов).
